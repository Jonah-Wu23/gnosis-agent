# GNOSIS：ECAI 投稿前优先实验计划

2026-10-08。目标为 ECAI 2027 主会研究论文，本轮新增 API 预算 **¥152.82**，按实际支出管理。

## 1. 投稿目标与实验取舍

**新增预算应优先补足激活边界的机制证据，并确认持久经验在新增任务上的收益。** 现有结果中，GNOSIS 严格成功率为 67.33%，冻结执行费用较 fixed 降低 49.81%；四次成熟比较的证据复用为 0。历史上 10 种不同可执行源码全部声明 `GLOBAL`，说明验证范围尚未通过有效局部修复得到实测检验，机制实验具有最高优先级。

**可执行组件的独立贡献需要通过消融明确归属。** 现有 150 次 GNOSIS 留出执行包含 6276 条 E 组件事件，全部具有 `effects` 字段，非空数量为 0，组件主动工具调用数量也为 0；150 份 `first_effect_boundaries` 均为空。文本经验与可执行干预的贡献应分别测量，组件装载次数只描述运行状态。

**原有 arXiv 大纲保持原状，新计划作为投稿证据补充单独保存。** 本计划安排三个实验：局部修复与验证复用、新增留出任务评价、冻结组件消融。三个实验分别检验方法机制、任务迁移和贡献归属，形成一组有明确分工的证据。

## 3. P1：局部修复能否产生真实验证节省

### 3.1 研究问题与干预

**有效的局部修复必须同时满足来源任务成功和作用范围受限。** 本实验从同一空组件基准分别修复三道已有 B1 失败题：`finance.xero_credit_allocation`、`operations.purchase_order_three_way_match`、`hr.airtable_learning_path_assignment`。三道题分属不同领域，选题依据是既有真实失败及不同接口操作需求。

**候选作用范围由修复模型依据真实接口语义选择。** 三个修复过程均可读取来源任务证据及合法工具接口，明确获得激活前不可见的协议说明，以及当前改动是否会触发全局验证的反馈；`GLOBAL` 仍然可用。模型可以添加文本经验或可执行组件，候选保留其真实 scope，研究过程不代替模型把全局组件缩成局部标签。

**三个独立候选共享空组件起点，以固定改动比较替代学习路径差异。** 每个来源最多分配 6 次任务执行，包含基准确认和候选执行；候选提议预算每个来源 ¥2，总计 ¥6。冻结各来源第一个严格成功的实际改动，未在额度内成熟的来源报告失败；所有来源均进入结果表，禁止按复用比例或机制题成绩筛选候选。

**既有全局组件不能通过改写 scope 自动获得局部验证资格。** 当前 `changed_units()` 同时检查旧、新单元，`GLOBAL→局部` 的修改仍包含旧的全局作用范围。采用空组件起点，使模型新产生的局部改动能够按其真实激活条件接受验证，避免旧全局依赖覆盖整个比较。

### 3.2 机制任务与执行矩阵

**固定的诊断任务集合将改动范围与任务成绩分离。** 从原有30道开发题中排除三个来源，每个领域按任务名排序后以种子20261008打乱，取3题，共18题；每题2次。候选模型只接收来源任务反馈，18题结果在三个候选冻结后统一揭示，机制题承担独立于来源修复反馈的诊断作用。

| 条件 | 版本 | 次数 | 用途 |
|---|---|---:|---|
| B0 | 空组件基准，第一批独立执行 | 18×2=36 | 构建历史轨迹与基准证据 |
| B0′ | 相同空组件版本，第二批独立执行 | 18×2=36 | 测量版本未变时的结果波动 |
| C1 | 财务来源的成熟候选 | 18×2=36 | 比较范围选择与全量验证 |
| C2 | 采购来源的成熟候选 | 18×2=36 | 同上 |
| C3 | 人事来源的成熟候选 | 18×2=36 | 同上 |
| 合计 | 三个来源均成熟时 | **180** | 共用相同B0证据 |

**范围选择必须在读取候选诊断结果前固定。** `validation_plan(B0,Cj)` 仅读取版本改动与B0轨迹；按范围模式首先执行受影响记录，并直接复用其余B0证据。随后，对原定复用部分执行候选版本审计，补齐全量验证结果，审计结果不返回候选模型。

**共同使用受影响记录使两种验证策略的差异集中在证据复用部分。** 全量结果由按范围阶段的新执行与后续审计组成；两种策略共用同一批受影响执行。完整审计的全部费用计入P1，按范围策略的实际费用另列，验证节省定义为审计补跑部分相对全量评价的费用比例。

### 3.3 指标与解释

| 指标 | 定义 | 回答的问题 |
|---|---|---|
| 成熟局部候选数 | 三个预定来源中，来源严格成功且改动不含GLOBAL的候选数 | 修复模型是否能形成有效局部经验 |
| 执行节省率 | 每个候选的复用记录数 / 36 | 影响范围是否排除真实历史执行 |
| 验证费用节省率 | 审计补跑费用 / 该候选完整36次评价费用 | 复用实际减少多少模型调用费用 |
| 发布判断 | 两种策略使用相同的正式发布规则：确定性改进加零退化；SAGE统计另报 | 复用是否改变发布结论 |
| 逐题得分差 | 按范围候选结果与完整候选结果的任务级差值 | 差异出现在哪些任务 |
| 无改动波动 | B0与B0′在相同记录集合上的得分差和成功不一致比例 | 独立API采样本身有多大波动 |
| 实际干预 | 非空effects、首次生效位置、主动工具调用及随后动作 | 局部组件是否真正改变执行 |

**真实API的独立采样要求同时报告复用差异和无改动波动。** 对每个候选的复用集合，分别计算B0对Cj、B0对B0′的不一致数量；三种候选共用的基准证据按同一任务相关数据处理。单个成功标签翻转进入逐题分析，发布结论使用完整任务集合中的一致规则计算。

**本实验的积极机制证据必须包含真实局部改动及非零节省。** 最有价值的结果是至少两个预定来源形成成熟局部候选，且每个候选同时存在受影响与未受影响记录；报告全部三个来源的实际节省及发布判断。若三个来源均形成全局改动或均未成熟，则本轮自主修复的局部性主张判为失败；若发现激活前输入被改写或未登记工具影响，则边界实现判为错误。

**判定一致率按实际候选数量报告。** 三个候选最多形成三对发布判断，正文写明例如“3/3”，并同时列出逐题分歧及B0′波动。新增正例的价值在于把执行依赖与真实节省联系起来，统计单位由候选和任务各自承担。

### 3.4 预定产物

一张候选表同时列出来源修复结果、作用范围、执行节省及费用节省；一张逐题矩阵呈现B0、B0′和三个候选的严格成功。原始版本、验证计划与全部执行ID保存于独立的 `experiments/ecai_2027/mechanism/`。

## 4. P2：60道新增任务上的冻结版本评价

### 4.1 研究问题与样本

**新增独立任务扩大对持久经验迁移的检验范围。** 从固定提交的任务全集中排除所有既有开发、选择、留出及中途检查任务，并排除其他已进入学习反馈或评价的任务。对剩余任务按领域分层，每个领域取10题，共60题；任务名排序后用种子20261008固定抽样，形成一次性冻结清单。

**三种历史冻结版本维持这次确认性评价的研究对象。** GNOSIS、global、fixed 使用原正式实验冻结版本，分别在60题上独立执行2次，总计360次；P1产生的新候选只进入机制实验。新任务结果不返回修复过程，性能差异归属于既有持久经验。

| 条件 | 任务数 | 每题重复 | 新执行数 | 原始均价估算 |
|---|---:|---:|---:|---:|
| Fixed | 60 | 2 | 120 | ¥22.62336 |
| Global | 60 | 2 | 120 | ¥13.88058 |
| GNOSIS | 60 | 2 | 120 | ¥11.35529 |
| 合计 | 同一批60题 | — | **360** | **¥47.85923** |

### 4.2 主要分析

**任务级成功比例与执行费用共同刻画冻结版本的部署表现。** 主指标为每题两次执行的严格成功比例，费用指标为同题两次费用之和；partial credit、输出token及工具调用次数作为机制解释。按领域列出任务级差值，跨领域汇总使用相同权重。

**三个预先规定的性能比较采用同一个多重检验集合。** 比较为GNOSIS对fixed、GNOSIS对global，以及P3的GNOSIS对无E版本；三项双侧任务级配对置换检验进行Holm校正，区间按任务成对bootstrap 200000次计算，随机种子100。置换使用1000000次符号重采样并采用加一校正，避免把120次执行当作120道独立任务。

**60道任务的作用是提高覆盖度并测量效应大小。** 按两次重复下任务配对差标准差0.35的规划假设、双侧Bonferroni阈值0.05/3及80%功效，正态近似的可检出差异约为14.62个百分点：\((z_{1-0.05/6}+z_{0.8})\times0.35/\sqrt{60}\)。现有五次重复下的配对标准差约0.20–0.21，两次重复采用更保守的0.35；实际判断由新样本区间和检验结果决定。[配对功效计算定义](https://www.statsmodels.org/dev/generated/statsmodels.stats.power.TTestPower.power.html)

**新增60题与原30题分别承担新评价和历史结果的展示。** 新60题独立成表，原30题保留现有五次重复结果；如附录给出90题汇总，每题先在自身重复次数内求平均，再按任务等权汇总。独立样本的新增来自任务身份扩展。

### 4.3 预定产物

主表报告三组严格成功率、任务级区间及冻结执行费用；配对差图按60道任务呈现变化；token与工具调用统计解释费用来源。三项检验由随实验保存的脚本执行，统计过程与结果一并保存于 `experiments/ecai_2027/heldout_new/`，任务清单与原有清单分开。

## 5. P3：可执行组件的独立贡献

### 5.1 干预与共用对照

**移除唯一E单元能够直接检验它对冻结版本的贡献。** 消融版本从原GNOSIS冻结版本中移除 `ace_op_vp_guard`，其余13个文本单元的内容、顺序及作用范围保持一致；消融版本不继续学习。60道新题各执行2次，共120次，完整GNOSIS对照直接使用P2的同批结果。

**完整版本与消融版本应在同一任务块内交错执行。** P2与P3共享任务初态和模型条件，四个条件在任务内按预定随机顺序轮换，避免不同时间及缓存预热顺序固定归属于某一组。移除E单元的影响通过任务结果及真实干预记录解释。

### 5.2 指标与结论规则

| 指标 | 分析 |
|---|---|
| 严格成功率差 | 纳入P2规定的三项Holm比较；给出任务级区间 |
| Partial credit差 | 次终点，与主指标分开报告 |
| E组件干预率 | 完整GNOSIS中至少一次非空effects的执行数 / 120 |
| 费用与工具调用变化 | 同题比较完整版本与消融版本 |
| 触发任务表现 | 展示实际生效任务的轨迹与结果，并明确其为执行后形成的分组 |

**贡献结论由实际干预与性能变化共同决定。** 若新题中组件仍无实际干预，运行证据支持将该批冻结执行收益归于文本经验路径；若出现干预且消融降低成功率，则逐题解释组件修改如何改变任务终态。差异区间覆盖零时报告区间，等价性结论需要另有预设等价界限。

**零干预的历史发现使这项消融具有明确的架构价值。** 原150次执行中的6276条E事件均无effects，直接提供了检验预期；120次新增消融执行确认这种现象是否延伸到新任务。论文对可执行经验的主张由实际生效任务支撑，文本经验的价值保留在完整的性能比较中。

### 5.3 预定产物

一张完整GNOSIS与无E版本的配对表，以及干预率和费用变化的联合分析。版本及执行保存于 `experiments/ecai_2027/ablation/`，共享P2对照通过原始执行ID关联。

## 6. 执行条件与费用约束

**实验条件沿用正式实验设置，使新增证据可解释。** AutomationBench固定提交 `4a8e106`，DeepSeek官方 `deepseek-flash`，思考开启、`reasoning_effort=high`、温度1，最多50步，单次输出上限393216。每次任务重置环境；服务断流恢复沿用项目规则，失败尝试的实际费用全部归入本轮支出。
