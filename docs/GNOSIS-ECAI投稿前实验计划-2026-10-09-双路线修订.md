## 4. P4：作用域界面的真实修复对照（¥90）

### 4.1 六个来源与两组任务集合

开发集某领域缺少合格来源时，选取范围扩展到该领域原正式实验的 fixed 留出记录：任务名排序后按种子 20261009 打乱，取第一个具有完整真实失败轨迹的任务，冻结其按重复序号排列的首次合格失败轨迹。客服来源依此登记为 `support.reamaze_intercom_migration`。该题保留原实验中的历史留出身份，本轮登记为 P4 修复来源；P4 机制面板和 P2/P3 新增留出集均排除该题。筛选只读取既有记录，新增筛选调用为零。该条款在 P4 首次调用前修订并冻结；已有后续调用时须登记新批次。

新来源各运行一次空组件基准，用于同时报告当前基准成功与历史失败。A/B 统一使用该来源预先冻结的历史失败证据；当前基准成功也保留来源，并标记自然波动。某领域没有合格失败来源时，记录来源缺额，六来源完成条件不成立；不能换入其他领域后仍声称满足原设计。

### 4.2 唯一界面处理与生成规则

两组共享同一失败轨迹、任务目标、合法 scope 清单及工具说明，模型配置相同。两组均允许文本单元与 TypeScript 组件，均可选 GLOBAL，执行层接受同样的 `edit` 能力。

- **A：原始提议界面。** 保持现有 `edit` 提议结构。
- **B：结构化作用域界面。** 在相同 `edit` 能力上填写 `service`、`endpoint/tool`、`activation_predicate`、`intended_effect`、`pre_activation_visibility` 和 `scope_rationale`，再输出模型自主选择的合法 scope。GLOBAL 与局部 scope 都填写相同的理由字段；无对应项填写明确的空值。

研究处理是这套结构化界面的整体效应。B 新增字段只用于提议和记录，执行前转换到与 A 相同的单元结构；字段不额外注入运行时上下文。宿主已有激活语义是登记 hook 与 service／endpoint／tool 标识匹配。`activation_predicate` 必须能落到现有语义，任意自然语言条件不自动获得执行能力。静态检查只检查协议、注册能力和类型；语义解释由研究者结合源码与轨迹完成。

每来源每界面独立生成两份候选，共 `6 × 2 × 2 = 24` 个固定提议槽位。每份从空组件独立生成，不读取其他提议及候选评分。来源内 A/B 调用顺序按种子 20261009 预先随机，重复序号仅用于组织配对。服务重试与一次格式重试属于同一槽位，不计成新提议；两次格式失败的槽位记为失败。

每份合法、非空且可装载的候选在来源任务上真实执行一次。严格成功后冻结为成熟候选；失败候选完整保留，不再根据失败反馈修复。所有成熟候选进入机制审计，禁止仅选择局部候选或表现最好的候选。无效提议和运行错误计入全部 24 个槽位的分母。

“成熟”采用一次来源严格成功的操作定义，同时报告该来源空组件结果。若空组件也成功，则来源结果表示该次执行成功，单独列示其修复收益证据。两次独立提议衡量生成稳定性，候选的单次来源成功不转写成确定性修复保证。

### 4.3 完整运行与选择性验证

全部候选冻结后运行新 B0/B0′。对每个成熟候选 C，根据 `validation_plan(B0,C)` 生成 12 条选择计划，保存时不得读取 C 的机制成绩。范围采用整组改动并集；任何 GLOBAL 单元都会使全部记录进入重测。

先执行计划内受影响记录，其他记录引用 B0，形成选择性发布判断；再完整执行计划复用的记录作为审计，形成全量发布判断。受影响记录共享，避免两套策略各运行一遍。A/B 候选在同一任务块内按冻结顺序交错执行，各任务重置环境及组件状态。

发布条件沿用 P1 的严格成功均值改进、partial credit 平局判据及零退化条件；SAGE 单列。保存两种判断及分歧任务。研究期间只计算发布判断，不向外发布版本。

复用审计同时检查首次文本注入、工具目录变化、非空 effects、主动调用和登记激活位置。未受影响记录发生标签翻转时，与对应 B0′ 波动共同分析；随机生成的完整轨迹可以自然不同。明确出现激活前可见或登记范围外组件干预时，记录具体执行路径，判为契约失效。仅靠标签相同不能通过完整性检查。

机制面板同时存在受影响和未受影响记录，才进入局部复用评价。12 条均受影响时记录零节省；12 条均不受影响时标为“本面板无激活覆盖”，保留费用数据，但不计入跨激活边界验证成功的候选数。

### 4.4 主要终点与统计单位

**主要终点：每个界面的有效局部修复产出率。** 分母固定为 12 个提议槽位；分子同时满足：来源严格成功、整组无 GLOBAL、机制面板含受影响与未受影响记录、完整审计未发现可定位的未登记影响、选择性与全量发布判断一致、验证执行数减少。正式发布是否通过另外列出。

这个终点将生成失败和来源失败计入实际修复过程的表现。另报告合法提议率、来源成功率和成熟局部率，使产出变化可以追溯到具体阶段。对未审计完的候选标注未知，并给出全槽位产出率的上下界；未完成不冒充失败观察。

次终点为每候选重测比例、按实际调用核算的验证策略成本差、全流程费用、文本与 E 干预覆盖、正式发布通过率。费用按每个界面全部 12 个槽位计入；成功候选费用另列，避免忽略生成失败成本。

统计以六个来源为单位，每来源先平均两次提议，再计算 B−A 差异。主要终点使用六来源配对符号翻转检验，枚举 `2^6 = 64` 种，双侧 p 值；其解释依赖零假设下来源差值符号可交换。来源成组 bootstrap 200,000 次、种子 100，报告区间及六个来源的全部差异。原三来源与新增三来源分别列示，其他指标以效应大小和逐来源结果为主。机制任务和来源内重复不当作额外来源样本。

最多六个来源意味着双侧精确检验最小 p 值为 0.03125。现有设计适合识别强且跨来源一致的效应；较弱效应按实测区间呈现，不靠增加同一来源的提议次数扩充来源数。

### 4.5 对应的机制判断

| 实测关系 | 可以形成的判断 | 必须提供的运行证据 |
|---|---|---|
| B 提高有效局部修复产出，来源成功保留且验证费用下降 | 结构化作用域表达改变该系统的修复局部性及验证成本 | 同来源 A/B 成熟版本、激活覆盖、完整审计和全流程费用 |
| B 增加局部声明，但这些候选频繁来源失败 | 局部表达与来源执行有效性存在冲突 | 具体失败操作、依赖条件，以及 A/B 对应的执行路径 |
| 局部来源修复成功，但范围外出现实际干预 | 现有激活契约存在遗漏 | 触发条件、首次违规位置及独立重复观察 |
| A/B 都采用 GLOBAL | 六来源中全局化持续存在 | 源码和轨迹中的具体依赖；仅有 GLOBAL 比例不足以形成机制结论 |
| A/B 都能形成可靠局部修复 | 全局化对来源或运行条件敏感 | 与 P1 条件的明确关系，报告真实效应，终止界面优越性主张 |

费用浮动额度只用于执行预定槽位及恢复技术失败，不用于按发现追加确认实验。需要新干预才能定位原因时，投稿机制证据标为未完成，另行制定研究问题与预算。

## 5. P2/P3：18 道新增任务的收益与组件归属（¥30）

从 AutomationBench 固定提交中排除所有原开发、选择、留出、中途检查任务，以及曾用于学习或 P4 的任务。剩余任务每领域按名称排序，种子 20261009 打乱，取三题，共 18 题。实际任务 ID、四个版本和顺序在首次运行前冻结。

| 条件 | 版本 | 任务数 | 每题次数 | 新执行数 | 额度归属 |
|---|---|---:|---:|---:|---|
| Fixed | 原正式实验冻结版本 | 18 | 2 | 36 | P2 ¥22 |
| Global | 原正式实验冻结版本 | 18 | 2 | 36 | P2 ¥22 |
| GNOSIS | 原正式实验冻结版本 | 18 | 2 | 36 | P2 ¥22 |
| GNOSIS-no-E | 仅移除 `ace_op_vp_guard` | 18 | 2 | 36 | P3 ¥8 |
| **合计** | | | | **144** | **¥30** |

no-E 保持其他 13 个文本单元的内容、顺序及作用域不变，不重新学习。P1/P4 生成版本不进入这批评价。每道任务的四组各两次构成一个完整块，块内执行顺序预先随机；每次执行重置环境。

主指标先计算每题两次严格成功比例，再对 18 题等权平均。三项比较为 GNOSIS vs fixed、GNOSIS vs global、GNOSIS vs no-E；按任务配对，枚举 `2^18 = 262144` 种符号翻转做双侧检验，三比较 Holm 校正。任务成组 bootstrap 200,000 次、种子 100；报告差值及 95% 区间。附 partial credit、费用及工具调用数。

这批任务用于补充收益归属。原 60 题方案的功效估计不适用于 18 题；3–5 个百分点的历史差异可能对应较宽区间，未显著时保持差值与区间表述，不判为性能等价。原 30 题 × 5 次结果单独保留，新增 18 题单列，附录合并时按任务等权。

P3 报告 GNOSIS 36 次执行中的非空 effects 数、首次干预位置及动作变化。原冻结 E 与 P4 新生成 E 分表解释；P1 C2 已有 36/36 非空 effects，不用原冻结版本的零干预概括全部可执行修复。若 no-E 与 GNOSIS 的表现接近且原 E 持续无干预，则将当前冻结版本的收益证据主要归于文本路径，并报告区间。

## 6. 投稿路线裁决

P1 原正结果 FAIL 保持冻结。P4 的正向结果作为“界面干预恢复验证局部性”的后续发现，与 P1 全局化现象共同组成机制论文。论文主线由完整结果决定。

### 6.1 界面干预机制达到投稿准备条件

以下条件同时满足，标记该机制证据 PASS：

1. 六个来源的 24 个提议槽位均有明确结局，所有成熟候选完成完整审计；没有将预算中断计作观察失败。
2. 主要终点 B−A 为正、双侧精确检验 p≤0.05；新增三来源中至少两个出现同方向改善，逐来源结果完整公开。
3. 至少两个来源的 B 候选有真实局部激活与未激活记录、完整审计支持复用、发布判断一致，按相同成本边界的验证策略成本下降。
4. 全流程成本计入失败提议及审计，P2/P3 完成收益归属；机制解释明确到界面处理、版本范围与运行路径。

这组条件是本研究预先登记的证据要求。论文原创性需结合相关工作另行审查；内部 PASS 不直接作为会议录用判断。

### 6.2 持续全局化或契约失效

若主要终点没有显示界面改善，继续按完整轨迹判断原因。形成独立机制主张需有明确触发条件，并在至少两个来源上重复观察到相同运行关系，其中至少一个来自新增来源层。局部候选来源失败须展示具体依赖如何阻止修复；契约失效须展示登记范围外的真实影响。

只有全局率、零节省或成绩波动时，标记 **机制贡献 FAIL**，产出诊断性研究。出现多个解释且缺少区分它们的干预时，标记 **机制证据未完成**。不把 P2/P3 的小幅差异作为机制缺口的替代证据。

| 最终证据 | 论文方向 |
|---|---|
| P1 全局化，P4 界面干预达到 6.1 条件 | 作用域表达如何决定自主修复的验证经济性 |
| P4 给出可重复的局部有效性冲突或契约失效 | 明确条件下的修复失效机制 |
| P4 只有提议措辞改变或持续 GLOBAL | 个案诊断，ECAI 主会机制准备 FAIL |
| P4 或 P2/P3 缺少完整预定数据 | 报告完成率，投稿准备未完成 |

论文标题可采用 *Scope Interfaces and Validation Locality in Self-Evolving Agents*，最终按实际发现定稿。ECAI 官方评审对负结果的评价依据见 [ECAI 2024 PC 指南](https://sites.google.com/view/ecai24faq/pc-members)；投稿日期、篇幅及匿名要求在提交前以 [ECAI 官方网站](https://ecai2027.org/) 的当届征稿通知核实。

## 7. 费用模型与执行契约

每个实验分开记录修复提议费用、来源执行费用、验证费用和冻结部署费用。选择性策略的费用取受影响记录的实际支出，全量策略的费用取完整候选记录支出；相同受影响执行只计一次科研支出。

审计复用记录也真实消耗了现金。策略差额表示在相同记录上核算的可节省验证费用，实验期间实际支付的是完整审计费用。两项同时报告，避免把策略节省从官方账单中扣除。

对部署 N 题，按同一阶段边界计算：

\[
C_{\mathrm{total}}(N)=C_{\mathrm{proposal}}+C_{\mathrm{source}}+C_{\mathrm{validation}}+N\bar c_{\mathrm{deploy}}.
\]

共享基准费用在实验总账只记一次，A/B 策略比较中采用相同分摊方法；全流程收益以各组实际失败成本计算。验证策略成本下降与全流程成本下降分别判定。收支平衡点仅在所比较的部署均价差方向支持时计算。

固定条件沿用 P1：AutomationBench 提交 `4a8e106`、`--toolset api`、最多 50 步；DeepSeek 官方 `deepseek-flash`，thinking 开启、`reasoning_effort=high`、温度 1、单次输出上限 393216。官方 API 在闲时运行，任务执行最多八路。执行条件发生变化时停止复用旧条件记录，保存实际版本信息。

服务断流最多重试十次，指数退避 2–60 秒；格式错误重试一次。失败尝试真实记账，未完成槽位保存失败状态。余额不足退出并保留断点。评分器及发布门禁处于受测 Agent 权限之外，QuickJS 与操作系统隔离保持启用。

P4 审计按来源顺序完成两个界面的全部成熟候选，再进入下一来源；来源顺序预先随机。P2/P3 按完整八执行任务块恢复。配对块是分析完整性单位，未知 token 费用以预留管理；块中途额度不足时保留已完成结果，标注不完整并优先恢复。
