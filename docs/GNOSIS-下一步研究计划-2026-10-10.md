# GNOSIS 下一步研究计划：知识提供时机与更新验证边界

## 1. 研究决策与关键假设

**当前 ECAI 主会判断为 FAIL。下一步主攻一条路线：解释知识提供时机如何改变修复收益与验证覆盖，并形成能够在新任务上预测的边界判据。** 停止扩大原 GNOSIS 学习效果比较；后续资金用于固定修复的受控干预，以及 SKILLAA 原生验证机制的外部审计。

本计划的 PASS 指达到项目的投稿候选标准。采用《什么样的失败才能投ECAI？》中“重要现象、明确边界、可验证机制、迁移价值”四项要求。具体证据门槛见第九节。

| 关键假设 | 撤掉假设后，结论是否成立？ |
|---|---|
| 一部分真实修复包含首次关键决策之前需要的知识 | 时机主张失效；终止“延迟导致修复失效”的主张 |
| 同一正文可以在固定路由与消息规则下改变首次可见时刻 | 时机因果解释失效；必须先修正实验接入 |
| 固定路由能够在执行前选中相关知识，并保留部分未暴露任务 | 局部提前方案失去验证节省空间；如全部选中，按全量验证计费 |
| 模型和环境的自然波动可以用同期无编辑重复估计 | 标签翻转的机制归因不成立；需要补齐无编辑重复 |
| 存在未参与设计的真实任务模板和独立修复来源 | 新任务预测结论不成立；旧任务继续承担发现机制的用途 |
| SKILLAA 原生单次编辑与门禁可以由官方代码执行 | 外部验证尚缺证据，主会 PASS 保持未满足 |
| ¥91.34 为最新官方余额，四条历史未知调用尚有 ¥6.46070177 待核清责任 | 资金安排随核清结果调整；已结算费用不重复扣除 |

| GPT | 执行前预测、按来源隔离、无编辑重复、过程证据 | 冻结预测器后检验新模板；统计单位为独立来源；结果与过程共同支持机制 |
| google | 知识暴露、真实调用与验证成本的联系 | 分别记录输入暴露、行为变化、任务回归和门禁决定；费用逐次计算 |
| Qwen | 规划契约、依赖边界与恢复行为 | 增加“固定契约提前、正文延迟”对照，保留模型自然重新规划的能力 |

**新颖性集中在验证边界。** [TipsWarm](https://arxiv.org/abs/2609.32339) 已研究检索前及时提供指导；[SkillSandbox](https://arxiv.org/abs/2610.10088) 已研究通过新场景评估技能的可复用性。“提前提供有帮助”和“小范围测试技能”都已有直接工作。本研究需要新增：同一修复的时机干预怎样改变验证集合，以及执行前的判据能否预测这种变化。

[SKILLAA 论文](papers/2609.20455v1.pdf) 已有技能学习的正结果，也已有环境与模型条件下的收益差异。后续使用其原生 LocalGate 与 BigGate，检验历史使用记录覆盖更新影响的条件。研究问题围绕具体门禁决定展开。

选择性重测已有成熟软件研究基础。本研究在此基础上刻画 Agent 特有的知识可见性与模型决策依赖。

## 4. 统一研究对象与可检验命题

一次研究对象为 `(宿主版本，任务 x，旧知识 K，单次编辑 Δ，提供策略 π)`。固定正文与工具权限，只改变 π；涉及正文拆分的处理另设对照。

对每个对象分别记录：

- **首次可见时刻**：新增正文第一次进入实际模型请求的位置。hook 触发和 E 组件执行分别记录。
- **决策截止点**：完成某项任务约束所需的最早关键决策。由任务要求与 API 行为在新结果产生前确定，例如读取迁移规则必须早于首次目标写入。允许不存在明确截止点。
- **预测重测集合 R**：执行新版本之前，按冻结策略选出的任务。
- **实际变化**：关键动作、任务断言与费用相对旧版本的变化；无编辑重复给出自然波动参照。

### 命题 H1：时机敏感性有可预测的边界

对于知识先于关键决策才有用的任务，推迟正文会降低成功率或增加恢复费用；对于纯执行细节修复，延迟造成的损失更小。主要检验是两类任务的时机效应差异。

在执行前依据任务与修复内容冻结类别。过程证据连接“正文未出现 → 关键动作已发生 → 约束受损或需要恢复”，并核对提前处理是否改变该动作。

### 命题 H2：提前可见与局部验证可以同时成立

若任务路由与规划契约在正文编辑前已经冻结，正文仅提供给路由选中的任务，则正文更新的结构性重测集合可以保持局部。路由或契约自身发生更新时，按其真实消费者扩大集合。

证明范围限定为宿主信息流：未入选任务的模型输入、可用工具和环境操作都不依赖 Δ，且没有跨任务共享可变状态。在这些条件下，未入选任务的执行分布保持不变。随机服务的两次独立采样仍可产生不同结果。任一前提失效，都需要重新确定依赖集合。

**正文更新与路由更新分别计费、分别验证；局部提前方案成立时，优先使用局部提前。** 全局暴露对应全局输入依赖，实际回归率由实验测量。

### 命题 H3：历史使用记录存在可预测的覆盖缺口

新知识可能影响历史未使用该节点的任务。预测器应在新版本执行前指出这些任务，并在保持相同验证调用量时提高回归捕获率。完整审计用于判定这个命题，合并候选的 BigGate 拒绝数单独报告。

## 5. GNOSIS 同内容干预实验

### 5.1 发现集与确认集

P1/P4 的全部来源及其机制任务作为发现集。先用已有请求与动作记录挑出确有任务知识的文本，检查删除后受影响的约束，完成分类规则。旧来源允许用于调试，结果不进入新任务的确认统计。

确认集目标为八个独立修复来源：四个预判具有规划依赖，四个预判主要修复执行细节。每个来源配三道真实任务，两道相关迁移任务、一道预测范围外任务；每道任务各处理重复两次。源任务只用于产生与确认修复，迁移任务的运行结果对提议过程保持隐藏。固定 240 次执行优先增加独立来源，以提高跨来源判断的辨别力。

从 AutomationBench 剩余真实模板中按冻结顺序选择，按任务模板隔离。已用于 P2/P3 的 18 题以及此前选取任务全部排除。同一模板的参数变体归入同一来源，按实际可用模板数登记样本。每个来源选取第一个满足合法性与来源效用条件的候选，全部提议计入数量和费用。

迁移题依据任务内容与修复知识的关联选取。确认阶段固定候选和来源，全部迁移结果进入分析。

### 5.2 五种处理

| 处理 | 内容与提供方式 | 直接回答的问题 |
|---|---|---|
| G：全局提前 | 正文在所有任务首个模型请求前可见 | 当前 GLOBAL 的效用与覆盖成本 |
| L：局部提前 | 冻结路由选中后，完整正文在首个请求前可见 | 提前提供是否确实需要全局暴露 |
| D：局部延迟 | 与 L 使用同一路由、同一正文，在预定真实边界后首次可见 | 固定提供对象后的时机效应 |
| C：契约提前、正文延迟 | 原正文预先分成契约和剩余正文；契约提前，正文按 D 提供 | 最小规划信息能否保留收益与局部编辑空间 |
| N：移除修复 | 保留公共宿主条件，移除该修复的全部任务知识 | 修复效用与无编辑自然波动 |

L/D 的路由由冻结的模型根据任务描述与技能契约判断，输出协议化的选择结果；运行代码负责结构校验。同一任务的路由结果缓存并共享，路由费用计入方法成本。

G/L/D 正文完全相同。C 在运行前完成信息保留的拆分，各部分沿用原句；L 的对应比较使用相同分段和顺序。契约一旦改变，所有曾读取契约的任务进入重测集合。D 若始终未触及预定边界，正文保持未提供，按处理定义分析。

五种处理采用相同消息角色与容器规则；除内容到达时刻外，避免系统消息与工具消息权重变化。运行时在发送下一次模型请求前执行注入，保存实际请求位置。原生 GNOSIS 的 system/工具返回注入行为作为已知工程现象单独说明。

延迟边界由任务中的真实操作定义。所有处理保持 50 步和同一权限，模型可自由重新规划。以实际模型请求记录正文可见时刻，并与关键动作的发生顺序比较。

主要实验固定函数能力与工具参数处理，干预文本知识。具有实际贡献记录的 E 组件作为后续边界验证对象。

### 5.3 预测器与验证集合

预测器输入为任务描述、旧版本证据和冻结的编辑差异。一次模型判断输出知识需求、最晚提供边界，以及需要重测的任务 ID。开发在发现集结束，确认集执行冻结规则。

比较三种集合：历史实际使用集合、宿主可见性依赖集合、加入执行前预测的集合。全量集合提供审计参照。预测集合的大小限制在开发集选定，并在确认阶段固定。

每个修复的三题构成一个预先登记的完整审计池。五种处理对池内全部任务执行，因此选中和未选中部分都有观测。覆盖率按各修复对应的任务池计算；扩大覆盖时追加对应的“修复 × 任务”执行。

费用至少报告完整审计成本、选择性验证成本，以及路由和预测调用成本。已有实验为测量付出的全量审计费用照实保留；另计算部署一次更新时可省的费用。

## 6. SKILLAA 原生单次编辑审计

使用[官方仓库](https://github.com/Ziqiao-Shang/SkillAA)，固定提交和任务快照，保留完整图提供方式、使用追踪与两级门禁。实验采用 SearchQA 的真实数据子集。

SKILLAA 的静态问答在一次作答前提供完整图。外部实验检验 H3 及可见性依赖，GNOSIS 负责 H1 的交互时机证据。

优先复用能取得的真实编辑与旧图；如官方未公开相应运行资产，通过原生提议流程产生。使用项目现有 DeepSeek 官方服务完成机制迁移，记录模型与运行配置。

目标取至少三个来自不同来源题的合法单次编辑，包含原生 LocalGate 接受的编辑。每次编辑使用相同旧图独立执行，保留原生 LocalGate 集合；对完整审计池逐题运行编辑前后版本。起始规模为每次编辑 12 道真实题，至少半数处于 LocalGate 集合外；每题旧版本与新版本各一次，共 72 次。另安排 24 次旧版本重复或关键分歧复测，合计 96 次短任务执行。LocalGate 所需题目超出该池时追加执行并计费，不缩减原门禁规则。

逐项识别以下结果：

| 观察 | 归因要求 |
|---|---|
| 单次编辑在 LocalGate 范围外造成回归 | 编辑独立于其他修改；重复后仍超过同期无编辑波动 |
| 单次编辑在范围内造成回归但门禁接受 | 按净收益接受规则解释，并报告被接受的回归 |
| 合并后新增回归 | 额外运行对应单次编辑后，才归因于编辑交互 |
| 使用记录缺失或不完整 | 按原生 UnknownUsage 规则确定是否应当进入验证 |

原生 LocalGate 的 DirectSources、PriorUsers、UnknownUsage 和 GroupSiblings 全部保留；BigGate 的净收益规则保持原样。漏检按单次编辑在 LocalGate 集合外造成的回归逐题计数。

冻结的预测器与历史使用集合在相同任务调用量下比较。外部成功标准是：至少两个独立编辑来源出现可重复、被预测器提前捕获的范围外回归，且额外预测费用计入后仍有实际价值。报告回归捕获率及其置信区间。

## 7. 统计与证据链

主要效应为 L 相对 D 的严格成功率差，并检验规划依赖与执行细节两类来源的效应差异。G 与 L 检验暴露范围，C 与 L 检验契约是否足够；N 提供真实修复增益和重复波动。

按来源计算效应，再聚合来源；任务与重复执行保留嵌套关系。唯一主要检验为预判任务类型与 L/D 时机效应的交互，显著性水平 0.05。其他组间比较组成次要检验族，使用 Holm 调整。外部验证单独报告独立编辑的重复机制证据和捕获率区间。

统计包含八个独立来源，同来源重复用于估计执行波动。四对四来源的标签置换有 70 种分配，双侧最小 p 值约为 0.0286；这种检验依赖零假设下来源效应可交换。任务类型属于观察属性，交互用于验证预判的区分能力；时机效应的因果解释来自来源内部随机安排的处理顺序。首次调用前核对检验假设与可达到的精度。

过程指标为首次可见位置、截止点违反率、恢复调用数和费用。轨迹审阅隐藏处理成绩；存在多个合理截止点时标记为“不确定”。确认分析同时呈现全部样本与预先能清楚分类的样本。

选择性验证报告：重测比例、严格回归捕获率、范围外回归数、接受决定是否改变，以及真实费用。自然波动按同一任务的无编辑重复估计。不存在真实回归时，回归召回率记为未定义。

L/C 相对 G 的效用用配对差值及区间呈现。不劣效分析预先规定可接受损失与所需区间精度。零漏检时给出单侧上界：独立样本 n 的上界为 `1 - 0.05^(1/n)`，n 按独立来源计数。

先用一个已知来源检查五处理的真实请求位置，并完成 SKILLAA 宿主加载与单题真实调用，再进入冻结的新来源实验。确认阶段按固定清单执行，完成后统一进行统计检验。遇到接入错误时修复接入，核心假设被否定时终止对应实验，服务中断时保留断点。

必要代码工作集中于现有接入层：

- 在 `automation_adapter.py` 的模型请求边界提供文本，记录真实可见时刻；处理定义与原生行为采用不同实验版本。

- 在现有研究执行入口安排五处理完整块，保存真实费用和来源关系；沿用评分器与任务隔离。
- SKILLAA 使用官方执行与门禁入口，只适配模型服务及导出审计所需记录。

完成接入后运行项目标准检查，再用真实任务验证五处理请求与严格评分。验证通过后按冻结清单执行。
