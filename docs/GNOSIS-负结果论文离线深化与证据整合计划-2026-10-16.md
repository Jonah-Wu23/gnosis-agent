# 生命如何持续构造自己：GNOSIS 负结果论文的离线深化与证据整合计划

2026-10-16 · 目标：ECAI 主会实证研究论文 · 使用已有执行与版本记录，新增分析不调用模型

## 1. 关键假设与研究决策

| 关键假设 | 撤掉这一假设，哪些结论仍然成立？ |
|---|---|
| 原始请求记录忠实反映执行模型和编辑模型实际收到的内容 | 任务成败与费用仍可统计；反馈送达、经验表达的机制判断需要重新定位到输入构造 |
| 候选版本、执行轨迹与业务对象状态能够对应到同一次真实执行 | 保留能单独核实的事件；对应关系缺失的部分退出过程到终点的解释 |
| 业务义务能从冻结提示词及其授权资料中确定 | 原严格评分和冻结要求评分继续保留；有冲突的业务义务以分别采用两种解释的结果呈现 |
| 相同内容版本在相同任务和运行条件下可作为执行波动的参照 | 版本内容相同这一事实仍成立；只有运行条件一致的记录进入同版本比较 |
| 现有数据中至少存在可复核的反馈损失或功能表达失效 | 两因素实验的预设结果仍保留；论文的机制贡献需要缩减到实际找到的关系 |
| 生物学迁移能够形成明确的 Agent 研究对象 | Agent 的实证结果仍然成立；生命构建的叙事进入引言与讨论，正文按实际测得的功能关系展开 |

**推进 ECAI 负结果路线。论文研究持续自我构造需要经过哪些功能关系，以及这些关系在真实 Agent 中如何中断。** 现有材料足以启动完整的离线深化和论文证据组织。投稿主张最终服从业务评价与实际干预情况。

论文工作标题：**How Agents Construct Themselves: Feedback and the Limits of Functional Accumulation**。

中文工作标题：**生命如何持续构造自己：自进化智能体的反馈利用与功能积累边界**。

整项工作只采用一种论文结构：从生命维持功能组织提出问题，用自然修改历史追踪经验如何形成，再用冻结的同源干预检验迁移，最后提出可供其他研究复用的功能积累评价方法。评价缺陷放进这条论证，解释系统究竟保留和选择了什么。

## 2. 保留“生命构建—熵减体”的科学主线

生命的组织需要持续投入资源才能维持。遗传内容经过表达形成性状，性状在环境中接受选择，能够持续发挥作用的组织关系成为后续变化的起点。这个故事迁移到 Agent，最有价值的问题是：**外部反馈经过持续加工，究竟形成了多少可以再次表达、可以保留的功能？**

“熵减体”保留为论文的构造视角。Agent 部分直接测量功能组织：要求是否进入经验，经验是否到达行动，正确行为是否在后续任务中重现，以及获得这些结果付出了多少费用。热力学部分依托生命科学原文；计算部分给出各自的变量和单位。API 金额、token 数量及版本字符数都使用其原有单位。

生物学迁移安排如下：

| 生命构建中的关系 | Agent 中的研究对象 | 现有证据入口 |
|---|---|---|
| 从环境持续取得可利用资源 | 任务结果与业务反馈进入编辑器 | 原始编辑请求、263 条要求级历史标注 |
| 加工并保存组织结构 | 提出修改，生成持久经验和可执行组件 | 提议记录、版本差异、候选生成结果 |
| 结构经过表达产生功能 | 经验进入实际请求，组件在真实路径上产生效果 | 请求记录、组件事件、业务动作 |
| 已有功能成为后续活动的起点 | 后续同题表现、经验保留与迁移 | 带版本的执行、来源复测、24 道迁移题 |
| 环境中的选择维持有效组织 | 发布判断是否选中真实业务改善 | 原门禁记录、严格评分与业务状态对照 |
| 维持组织需要持续支出 | 学习、运行及验证的完整费用 | 各批账本、执行用量、候选费用 |

引言围绕一个矛盾展开：Agent 已经能够不断修改自己，持久结构也持续增长，但功能积累仍需逐环节兑现。论文追踪这段构造过程，并回答哪些环节已经成立、哪些环节持续流失。

旧 EVO-PATH 的离线发现已经登记：可定位的自然表达或继承损伤为零，合格维护亲本为零。因此，“修复组织损伤恢复后续演化能力”维持已终止状态。本文的生命故事围绕已经发生的反馈加工与功能表达展开。Bloom 等关于稳定性支持可演化性的结果，用于解释为什么值得关注组织条件；Agent 中维护收益的实证主张由已有干预结果决定。

正文用一个向量描述功能积累：来源任务收益、迁移收益、已验证功能的保留、表达机会中的实际到达、完整费用。各项分别展示。相反方向的变化保持可见。

方法部分围绕三个可以直接回答的问题组织：外部反馈有没有转化为持久修改；持久修改有没有表达为正确功能；已经确认的功能有没有在后续适用机会中保留。任务成功定义为其全部适用业务义务完成。候选功能变化定义为同批、同任务条件下相对亲本的业务结果变化，已有能力的保留则在先前已经验证的要求上单独追踪。

这套关系允许出现反馈已经写入、编辑理由却没有明确选择它的路径。统计先恢复真实事件连接，再计算阶段之间的条件比例。阶段比例只在上下游集合确实嵌套时相乘。

这套构造视角产生三项可检验推论：持久内容增加时，业务功能仍可能保持不变；相同内容版本之间的结果变化可以显示执行过程的波动；来源题上的功能形成与新题中的功能表达可以分离。三项推论分别对应历史版本、同版本参照和来源到迁移的分析。

## 4. 离线工作的范围与执行方式

分析使用现有 JSON、JSONL、SQLite 及原始文本。标准格式由成熟库读取，Python 计算统计量，现有官方评价逻辑用于重放已记录动作。绘图使用真实分析结果。

现有模型生成的标注作为待核实材料。新的语义结论通过研究者阅读任务资料和执行记录形成；程序负责关联身份、定位引用和计算明确条件。对任务含义或适用性的判断不使用关键词词典，也不使用正则替代阅读。新增语义判断不调用远程模型、本地模型或 embedding 服务。

全部新增结果写入 `experiments/negative_result_offline/`，该目录已由项目现有 `.gitignore` 覆盖。既有冻结实验与原始 verdict 保持封存，新评价和新统计另存。文献核对采用已有本地论文与作者、出版方原文，联网仅用于补足书目信息和读取原文。

## 5. 统一事件与证据：先恢复系统实际经历了什么

先建立一份能够从论文结论回到原始事件的研究数据库。核心对象采用已有身份：执行、提议、候选版本、要求和评价。每条关系保留来源文件与 JSON Pointer；文本记录采用文件位置和上下文。

需要完成的工作：

1. 将历史抽取表、65 次编辑和本次六块实验对应到唯一执行。快照、WSL 原件、恢复批次及导出材料之间建立引用关系，重复拷贝只计一次执行。
2. 恢复真实父版本与候选版本关系。版本继承、工作区切换、候选提议和正式发布分别登记；读取已有候选不增加一次修改。
3. 将格式重试、服务重试与逻辑提议对应起来。失败调用保留费用，生成候选的数量按实际逻辑机会统计。
4. 逐批恢复模型参数、工具权限、初始 WorldState 和评价版本。共享条件相同的记录形成可比较集合，跨批次变化逐项明确。
5. 按原实验规定排除 2026-10-07 之前的报废记录。旧记录中的任务暴露仍用于核实选题隔离。
6. 单独列出终止、服务失败、余额不足和缺少后续评价的记录，使生成失败、执行失败和未观察到结果各自保留。

数据库包括七类关系：执行及其输入状态、提议及其结局、版本继承、要求在反馈链中的事件、业务要求评价、评审来源、费用。现有文件中的同一内容引用相同版本身份，避免重复存储轨迹全文。

完成后的直接产物是一张完整研究地图：哪些历史用于发现问题，哪些任务参与过方法选择，哪些结果来自冻结的独立迁移评价。论文中的样本数量全部从这张地图生成。

## 6. 核实两因素实验究竟改变了什么

这是整项分析最先完成的解释工作。

**来源触发。** 对六次来源首跑逐项核对原严格评分和真实业务义务。HR、marketing、operations 的运行分支由严格通过触发，四组因此保持祖先。进一步检查这些来源首跑是否存在严格评分遗漏的真实业务失败；若存在，形成“评价信号使学习没有启动”的完整事件链。

**候选生成。** 对 24 个计划槽位给出实际结局：未触发编辑、合法候选、格式失败、整理失败，以及实际费用。现有状态显示 12 个槽位未触发、9 个合法编辑、3 个编辑失败。核对重试记录后形成最终数量。未触发编辑在正文中按发生的行为命名。

**反馈事实。** 阅读实际编辑请求及三份已触发来源的 F1 整理结果。逐条核对整理内容能否回到来源，是否引入来源未给出的取值，是否遗漏了原始证据。确认 F0 和 F1 实际获得的事实集合，并登记整理增加的输入长度及计算费用。

**表示落实。** 对 R1 逐个检查新增和修改单元的结构字段及其实际内容。先确认格式条件，再阅读适用条件、规避要求与指导之间的关系。检查原有单元原样保留时，候选到底有多少内容接受了表示干预。

**实际输入。** 候选文件与真实请求逐项对应，明确文本经验是否实际出现、组件是否装载。版本相同的比较继续核对任务、初态、输入与权限。时间戳和执行身份单独保存，比较任务内容时只处理具有明确协议含义的元数据。

**内容变化。** 将合法候选与祖先逐单元比较，记录增加、移除和改写。语义阅读回答：改动修复了什么要求，写入了哪些来源对象，哪些条件可以用于迁移题，哪些内容只服务来源题。生成一张“反馈—改动—来源复测—迁移行为”对应表。

这部分最终回答：完整流程在哪一步停止，格式要求造成了多少生成流失，真正进入执行的修改是什么。它决定论文如何描述反馈组织和边界表示的结果。

## 7. 完成业务要求评价，让论文测量功能本身

先对 24 道迁移题和 6 道来源题重新通读提示词及其授权原始资料，形成完整要求集合。每条要求明确对象、行动或应保持的状态，并保留适用条件。顺序要求和通知与写入的一致性分别表达。

需求集合须在查看新增评分汇总之前完成。复核视图继续隐藏实验臂和版本名称，并保留同题统一要求；人工复核的时间顺序按实际发生记录。

建立三份结果，各自保留用途：

| 结果 | 内容 | 论文用途 |
|---|---|---|
| 原严格结果 | 官方断言按原实现求值 | 与原基准及既有报告对应 |
| 冻结要求盲审结果 | 现有 432 份 verdict 及其冻结统计 | 完整呈现预先登记并已经执行的分析 |
| 完整业务要求复核 | 原协议要求覆盖的全部义务及其实际状态 | 形成论文的业务功能评价，同时说明补充分析的形成时间 |

任务义务发生冲突时，逐条回到来源优先关系。能够依照原任务授权解决的冲突给出统一处理；仍有两种成立解释的条目分别评分，并对所有实验臂使用相同解释。环境中没有承载政策的资料、接口返回 404 和写入未实现分别登记。完整任务完成率、可执行义务的完成情况同时呈现。

新增要求覆盖全部 432 次评价；30 次来源首跑与复测采用同一业务要求体系。已有的正常返回、拒绝或错误状态原样保留。

重点核查四类关系：

- 应当改变的对象是否确实改变；应当保持的对象是否被改动。
- 金额、币种和数量是否与实际写入一致，通知是否如实描述对象状态。
- 必要行动及顺序是否成立，条件不适用时是否正确停止处理。
- 声称创建的文档或记录是否具有任务要求的内容，合并和迁移是否体现在目标对象上。

程序可以核算对象身份、明确数值和操作顺序；采用 `Decimal`、成熟日期库及 JSON Pointer。语义授权和对象适用性由阅读确定。重放只执行已有记录中的动作，使用与其相符的本地官方环境，检查动作效果和评分逻辑。

对每条引用核对三个层次：位置存在、内容支持该判断、内容属于正确对象和时间。代理自己的摘要进入“汇报”证据，实际对象状态进入“执行结果”证据。空引用删除后的有效证据按相同原则复核。

完整复核后，列出各评分体系之间新增通过、取消通过及排名变化。评价缺陷由明确的业务分歧数量和方向支撑。

## 8. 复原负结果的统计含义

独立计算冻结六块主比较，复现效应、64 种符号组合、p 值和区间反演。原始 `analysis.json` 保持封存；新程序输出可逐步核对的中间量。检查反演接受集合、网格分辨率和端点，按其真实集合报告。

主要研究以下层次：

**完整流程的结果。** 六块全部保留，编辑未触发和生成失败继续属于方法运行结果。原预设的 +10 个百分点目标及其判定完整呈现。

**编辑触发的来源。** finance、sales、support 形成来源首跑失败后的三块集合。按相同规则比较其结果，保留格式失败。此集合由编辑之前的共同来源首跑确定，用于描述流程进入编辑后的表现。三块与六块结果并列。

当前两部分的平均差异分别为：触发编辑三块约 −5.6 个百分点，未触发编辑三块约 −13.9 个百分点。两部分各占六块的一半，加权后得到 −9.7 个百分点。这个分解将实际编辑机会和同版本执行变化连接到主结果。

**合法候选的实际变化。** 每个合法候选与同批祖先、对应基准候选分别比较。实际合法性依赖处理条件，因此这部分承担候选诊断。合法率及失败费用继续进入完整流程结果。

**相同版本的波动。** 在内容版本、任务和运行条件一致的集合中，估计重复结果的分布。以三个未触发编辑的来源块为核心参照，检查相同版本的实验臂差值能达到多大、是否随任务或执行次序变化。该比较为观察到的负差提供量级。

## 19. 所有分析如何进入一篇有主干的论文

**自然修改历史。** 展示要求如何被选择和写入，说明表达链条中观察到的中断，配一条完整成功路径和一条完整失败路径。

**同源干预。** 按实际编辑触发情况呈现六块结果，展示来源与迁移、同版本波动及联合处理。原冻结结果与完整业务复核分别报告。

**同题修正与功能选择。** 解释携带轨迹在什么反馈条件下产生收益，同时展示评分与真实状态的分歧如何影响学习启动或候选选择。

**讨论。** 回到生命如何持续构造自己：总结哪些功能关系已经有证据，哪些阶段消耗了资源却没有形成可持续增益。给出后续研究可以直接采用的评价与记录原则。

## 20. 执行顺序、产物与论文结论的确定

| 顺序 | 完成的工作 | 产物 | 后续依赖 |
|---|---|---|---|
| 1 | 唯一事件、版本、执行条件和任务用途整合；核实编辑触发 | 统一研究数据库及事件地图 | 所有分析共用 |
| 2 | 30 道任务义务阅读、432 次评价与 30 次来源执行复核、评价来源核查 | 要求级结果与完整业务评价 | 主结果、案例和评分研究 |
| 3 | 冻结统计复现、同版本波动、候选状态与块贡献分解 | 主结果及固定敏感性结果 | 负结果的解释力度 |
| 4 | 历史反馈链、功能表达、后续保留与候选流失 | 过程关系与全部案例索引 | 机制解释 |
| 5 | 来源到迁移、携带轨迹、效率与完整费用 | 功能及费用的对应结果 | 适用范围与实际价值 |
| 6 | 相关工作原文核对、四条证据路径整合 | 论文证据稿与主图表数据 | 正式写作 |

这些工作构成完整执行范围。全部结果落入一个研究数据库、一份汇总结果和一份论文证据稿，图表直接读取数据库导出数据。分析入口拟集中在 `engine/negative_result_offline.py`，负责整合、业务评价汇总、过程追踪、统计与图表导出；人工判读保存在独立的要求与案例文件中。

验证采用现有真实数据：逐项重算已冻结结果；核对执行和版本关系；对已保存动作重放；检查表格与原始条目是否一致。新增分析代码运行后以其实际输出完成验证，不另造任务用例。

论文贡献按结果确定：

- 反馈到功能的完整中断链在不同真实任务中重复出现时，主张明确的功能构造失效关系。
- 编辑触发、生成失败和相同版本波动主导观察结果时，主张自进化研究需要显式测量实际干预与功能变化，并以本次完整流程给出证据。
- 完整业务评价改变方法排序或学习启动时，主张评价选择与真实功能积累之间存在具体偏差。
- 受控处理在完整业务评价下仍未达到预设实用目标时，将其写为所实施反馈组织与表示方法的实证边界。

ECAI 负结果论文的科学贡献可以来自严谨的实证边界，也可以来自可复用的评价方法。本文优先将两者与真实过程连接，使“生命持续构造自己”具有可逐事件检查的内容。

与负结果投稿标准的对应关系如下：

| 投稿需要回答的问题 | 本计划交付的证据 |
|---|---|
| 为什么这个失败值得其他研究者关注？ | 同一构造过程中的反馈利用、实际编辑与业务功能分离，并核对直接相关文献已经回答到哪里 |
| 失败在什么条件下出现？ | 实际触发编辑的来源、合法候选、相同版本参照、来源复测与迁移条件的完整结果 |
| 对失败有什么具体解释？ | 反馈到选择、持久内容到表达、评价到学习启动的原始事件链，以及既有受控对照对替代解释的约束 |
| 其他研究可以采用什么？ | 以实际干预和要求级功能为单位的评价方法、完整成本关系、可重新生成结果的分析入口 |

正式稿采用贡献已经兑现的表述：研究了什么构造关系，找到了什么中断，受控干预把解释推进到哪里，以及其他研究如何使用这些发现。每一项主张都以对应的真实事件和比较结果收束。
