\section{Derivation of evaluator exclusion}
\label{sec:exclusion-proof}

Let $h_t$ contain the complete source execution at learning step $t$, including actions and final world state. The official binary score is $Q(h_t)$; the complete business outcome is $B(h_t)$. The follow-up's eligibility rule is $A(h_t)=1-Q(h_t)$. If $A=0$, all four deployments retain the ancestor and no editing request is constructed. Thus, along any observed sequence of evaluator passes, this source produces no version change. Extra editing allowance leaves that control branch unchanged. Other tasks can still supply edits through their own eligibility decisions.

For a required action $D$, define $\mathcal B_D=\{h:D(h)=1\}$ and let $\mathcal Q=\{h:Q(h)=1\}$. Suppose the evaluator forbids $D$. Then
\begin{equation}
\mathcal B_D\cap\mathcal Q=\varnothing.
\end{equation}
A release rule preserving an incumbent's evaluator pass on this task therefore excludes every candidate trajectory in $\mathcal B_D$. The exclusion follows from the acceptance predicate even when a model can produce the correct action. It also holds independently of the price of validating the candidate. Removing the conflicting predicate changes the admissible set. Removing the preservation rule changes the consequence of a score loss. These are the assumptions needed for the release part of the main proposition.
