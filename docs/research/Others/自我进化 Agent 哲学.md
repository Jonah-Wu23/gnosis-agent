1. **能力—约束匹配律**  
   约束强度应与模型能力动态匹配。模型弱时，程序化限制、填表、兜底是必要脚手架；模型强时，过度外置逻辑会变成负担。自我进化 Agent 必须能评估自身能力，并逐步减少不再必要的硬性干预。

2. **语义判断归位：程序管形式，模型管语义**  
   程序擅长确定性、权限、资源、日志、验证、沙箱；语义理解、意图判断、风格权衡、复杂取舍应交由具备语义能力的模型。程序不应僭越为语义判断者，否则会与模型产生结构性冲突。

3. **硬边界与软引导分离**  
   安全、法律、权限、资源消耗等应是硬约束；流程、格式、风格、策略、角色表现等应是软引导。硬约束程序化，软约束模型化、可学习、可协商。否则“安全兜底”会膨胀成“全面限制”。

4. **脚手架消退与规则内化**  
   外置程序规则应被视为临时脚手架，而非永久牢笼。随着 Agent 能力提升，外部规则应逐步内化为模型策略、技能或习惯。自我进化的标志之一，就是曾经需要程序强制的东西，后来模型能自主稳定做到。

5. **日志即记忆，流程即版本**  
   输出、决策、执行流程保留在本地日志中，可复用、可复盘、可审计。自我进化 Agent 需要情景记忆、程序记忆和决策记忆，而不是每次都从零开始。

6. **Git 式分支、回溯与实验**  
   分支、回溯、复用机制类似 Git，意味着 Agent 应支持多路径探索、版本化自我、回滚失败实验、保留成功轨迹。进化不是单线前进，而是可分支、可合并、可回退的搜索过程。

7. **模块专精与上下文隔离**  
   填表、写剧情、推荐、代码、审查等应由不同模型或模块专门负责，各自拥有独立上下文和长期记忆。一个模型包揽一切，会导致注意力分散、上下文污染、角色不稳定。自我进化需要“专模专用 + 编排协同”。

8. **注意力是稀缺资源**  
   不要让单个模型同时管写作、表格、代码、脚本、质量审查和全局规划。认知资源有限，任务分解、职责隔离、上下文分区，是稳定性和鲁棒性的前提。

9. **隔离执行，但不隔离语义**  
   代码和工具应在沙箱中隔离运行，但数据进出隔离室时必须保持语义保真。隔离是执行层安全，不应变成认知层障碍。若数据流转阻碍了模型理解意图，隔离就伤害了 Agent 的智能。

10. **反过度防御与可控犯错**  
    过度防御、过度限制、凡事兜底，本质是不敢判断、不敢犯错。自我进化 Agent 必须有可控冒险能力：允许小错、记录错误、从错误中学习。无限兜底会抑制自主性，导致局部循环和全局停滞。

11. **全局哲学优先于局部补丁**  
    Agent 不能缩在某个局部反复修补，而要有项目级目标、价值函数和运行哲学。局部外置逻辑必须服从全局一致性，否则会形成“程序越写越多，模型越用越弱”的反进化结构。

12. **动态信任与自主权让渡**  
    信任不是静态的。初期可多控制，后期应逐步让渡判断权、规划权和决策权给模型，只保留最小必要硬边界。自我进化 Agent 的核心能力之一，就是知道何时该管、何时该放。

13. **反八股、反自我同质化**  
    要警惕 AI 写作味、模板化输出、固定流程依赖。自我进化不仅是能力增强，也是避免自我复制、自我僵化和内部循环。真实反馈、多样探索和外部校准必须持续存在。

一句话总纲：  
**自我进化 Agent 的哲学不是“用程序永远控制模型”，而是“约束随能力消退，语义判断归模型，程序退居安全网；记忆版本化、模块隔离化、全局哲学化、错误可控化”。过度防御是进化之敌。**
